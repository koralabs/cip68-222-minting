# Deterministic parameter HTTP fixture

The published 0.0.7 harness fetches `https://d1t0d7c2nekuk0.cloudfront.net/mainnet.json` during init. That hostname no longer resolves. `parameter-http-fixture.ts` replaces only that exact GET boundary with a real JSON Response and restores fetch afterward; unexpected hosts, methods and bodies fail rather than reaching the network. The real ContractTester.init, NetworkParams parser, compiler, transaction builder, evaluator and existing approval/denial assertions are not mocked or changed.

`network-parameters.json` is a static, unmodified serialization of `rawNetworkEmulatorParams` from the already locked and archive-verified @koralabs/helios 0.16.8-1. It is the library's documented offline unit-test baseline, not a recovered recording of the former mainnet endpoint or current chain parameters. It retains the complete protocol-7 cost model, 14,000,000 memory/10,000,000,000 step budget, 16,384-byte transaction limit, prices and fees. No limit or cost was loosened to force a contract pass. The initialization test compares the full parsed response to that locked export and separately asserts concrete fees, limits, UTxO price and execution cost.

The five parameter tests prove: real HTTP initialization preserves the baseline; unexpected hosts cannot escape to live networking; malformed JSON fails and restores fetch; corrupting the returned fee makes the same expected-output assertions fail; missing cost-model data still fails in the real parameter API. These tests cover the parameter boundary only. The existing datum-conversion HTTPS fixture remains a separate live dependency and is not falsely described as offline or deterministic here.

The harness regressions exercise actual Test.build using the unchanged tracked programs. Against published 0.0.7 they reproduced mint-redeemer/public-key-input and script-input-ordering failures, while public-key-only and missing-redeemer checks passed. After independent archive verification, the consumer intentionally migrated to corrected immutable maintenance release 0.0.10, retaining the same exact compiler identity; all four regressions pass. Nothing patches node_modules or changes expected outcomes to get green. No package is published by this consumer.

This enables repeatable contract unit evaluation against an explicit pinned baseline. It does not establish current-mainnet parameter accuracy, successful chain submission, or complete contract acceptance. All ten original approval/denial cases pass with the corrected release and fixture hashes matching the real harness's optimized compilation. Their expectations, tracked contract sources and compiler are unchanged; see the root-correction account in the repository README.
